## 小错误1
**笔记：为什么不能把 HttpSession 塞进 Result 返回**

现象：

```
return Result.ok(session);
```

报错：

```
HttpMessageConversionException: Type definition error:
[simple type, class java.util.Collections$3]
Caused by: InvalidDefinitionException:
No serializer found for class java.util.Collections$3
```

报错链路：

```
Result["data"]
  -> StandardSessionFacade["attributeNames"]
    -> java.util.Collections$3
```

原因：

1. `HttpSession` 是 Tomcat 的会话门面对象，真正类型是 `StandardSessionFacade`，不是普通业务数据对象。
2. Jackson 序列化时按 JavaBean 的 `getXxx()` 扫描属性，`getAttributeNames()` 被当成属性 `attributeNames`。
3. `attributeNames` 返回的是 `Enumeration`，实际类型是 `Collections$3`，它既不是数组、集合、Map，也没有可识别的 getter，Jackson 找不到序列化器。
4. Jackson 默认开启 `FAIL_ON_EMPTY_BEANS`，遇到无法识别的对象直接抛异常，而不是输出空 JSON。
5. 把 session 返回给前端还会暴露服务端会话内部状态，不安全。

结论：

`HttpSession` 是服务端容器对象，只负责保存会话状态，不能直接作为接口返回值。

正确做法：

```
// 验证码只用于日志/短信，不需要返回给前端
return Result.ok();

// 开发阶段想查看验证码，也只返回验证码字符串
return Result.ok(code);

// 需要用户信息时，返回 UserDTO 等业务对象，而不是 session
return Result.ok(userDTO);
```

一句话总结：

> 接口只能返回“业务数据对象”，不能返回 Tomcat 的容器对象；把 `HttpSession` 放进 `Result` 会导致 Jackson 无法序列化，并且不安全。

为什么要保存子啊threadlocal里面
![[Pasted image 20260827100228.png]]

这里是为了解决之前拦截器在对于没有访问页面,token没有刷新有效期的问题. 那么我们的思考就是, 首先肯定要拦截所有的情况,如果有token就刷新, 没有token就不管. 此时就会有一个问题, 没有起到拦截的作用啊, 那么我们就需要一个新的拦截器来进行评判是否能够进行登陆,如果 **一开始的想法就是token我们在进行查询一遍,但是没有必要进行刷新操作就可以了** ,这里解决最基础的问题, 优化也就来了, 我们要查询两次redis吗,假设在这个事件类redis又过期了怎么半, 多次访问速度也会降低. 我们就看看除了token之外还有什么能够判断的吗, **没错就是我们保存的thread local**

当前请求上下文（request context）,我觉得是重点Token 才是 A、B 两次请求之间建立关联的东西。保障生产的一样

thread更像是一个上下文(我觉得不好,这里信息只是长得一模一样,每次请求生成的是一样的信息而已),当我们进行多次请求的时候,这个时候为了拿到对应的信息,通过线程好获得.
给当前请求建立一个“临时的线程级上下文”，让这次请求后续执行的代码方便获取请求相关的数据。


preHandle()
postHandle()
afterCompletion()

| 方法                      | 时机                | 你的项目中的作用       |
| ----------------------- | ----------------- | -------------- |
| `preHandle()`           | Controller **之前** | Token校验、保存用户   |
| `postHandle()`          | Controller **之后** | 对结果/Model进行处理  |
| **`afterCompletion()`** | 整个请求**完成之后**      | 清理 ThreadLocal |
```
RefreshTokenInterceptor
        │
        └── preHandle()
              ↓
        Redis验证Token
              ↓
        UserHolder.saveUser()

LoginInterceptor
        │
        └── preHandle()
              ↓
        UserHolder.getUser()
              ↓
        判断是否登录

Controller
        ↓
      执行业务

RefreshTokenInterceptor
        │
        └── afterCompletion()
              ↓
        UserHolder.removeUser()
```
