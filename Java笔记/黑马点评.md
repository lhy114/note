## 小错误1
**笔记：为什么不能把 HttpSession 塞进 Result 返回**

现象：

```
return Result.ok(session);
```

报错：

```
HttpMessageConversionException: Type definition error:
[simple type, class java.util.Collections$3]
Caused by: InvalidDefinitionException:
No serializer found for class java.util.Collections$3
```

报错链路：

```
Result["data"]
  -> StandardSessionFacade["attributeNames"]
    -> java.util.Collections$3
```

原因：

1. `HttpSession` 是 Tomcat 的会话门面对象，真正类型是 `StandardSessionFacade`，不是普通业务数据对象。
2. Jackson 序列化时按 JavaBean 的 `getXxx()` 扫描属性，`getAttributeNames()` 被当成属性 `attributeNames`。
3. `attributeNames` 返回的是 `Enumeration`，实际类型是 `Collections$3`，它既不是数组、集合、Map，也没有可识别的 getter，Jackson 找不到序列化器。
4. Jackson 默认开启 `FAIL_ON_EMPTY_BEANS`，遇到无法识别的对象直接抛异常，而不是输出空 JSON。
5. 把 session 返回给前端还会暴露服务端会话内部状态，不安全。

结论：

`HttpSession` 是服务端容器对象，只负责保存会话状态，不能直接作为接口返回值。

正确做法：

```
// 验证码只用于日志/短信，不需要返回给前端
return Result.ok();

// 开发阶段想查看验证码，也只返回验证码字符串
return Result.ok(code);

// 需要用户信息时，返回 UserDTO 等业务对象，而不是 session
return Result.ok(userDTO);
```

一句话总结：

> 接口只能返回“业务数据对象”，不能返回 Tomcat 的容器对象；把 `HttpSession` 放进 `Result` 会导致 Jackson 无法序列化，并且不安全。
