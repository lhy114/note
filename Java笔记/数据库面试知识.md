MySQL 中，`MEMORY`、`MyISAM`、`InnoDB` 是三种不同的存储引擎。它们决定了数据库如何存储数据、如何加锁，以及是否支持事务。

其中，InnoDB 是 MySQL 默认的存储引擎，也是 Java 后端开发最需要掌握的。

这部分知识可以分为两个重点：

1. 三种存储引擎的区别：重点理解事务、锁、数据存储及适用场景。
    
2. InnoDB 的逻辑存储结构：重点理解表空间、段、区、页、行之间的关系。
    

## 一、MEMORY、MyISAM、InnoDB 的区别

### 1. 核心对比

|对比项|MEMORY|MyISAM|InnoDB|
|---|---|---|---|
|数据存储|内存|磁盘|磁盘（配合内存缓存）|
|支持事务|不支持|不支持|支持|
|锁机制|表级锁|表级锁|行级锁为主，也有其他锁|
|外键|不支持|不支持|支持|
|MVCC|不支持|不支持|支持|
|崩溃恢复|数据可能全部丢失|恢复能力较弱|支持事务崩溃恢复|
|典型场景|临时性、高速访问数据|以读取为主的非事务场景|常规业务系统|

### 2. MEMORY：数据主要放在内存中

例如：

```
CREATE TABLE test_memory (
    id INT PRIMARY KEY,
    name VARCHAR(50)
) ENGINE = MEMORY;
```

特点：

- 数据存储在内存中，访问速度可能比较快。
    
- 不支持事务。
    
- 主要采用表级锁，并发写入容易发生竞争。
    
- 数据在 MySQL 服务器重启后会丢失，但表结构通常仍然存在。
    
- 支持 HASH 和 BTREE 索引，默认使用 HASH 索引。
    

注意：MEMORY 并不是 Redis。 它属于 MySQL 的存储引擎，受 MySQL 的管理方式和锁机制约束，不应该简单认为它能替代 Redis 缓存。

### 3. MyISAM：传统的磁盘存储引擎

例如：

```
CREATE TABLE test_myisam (
    id INT PRIMARY KEY,
    name VARCHAR(50)
) ENGINE = MyISAM;
```

特点：

- 数据存储在磁盘中。
    
- 不支持事务，无法利用 `ROLLBACK` 撤销已经执行的普通数据修改。
    
- 采用表级锁，写入时可能影响其他查询或写入。
    
- 不支持外键约束。
    
- 缺少 InnoDB 那样的事务日志及崩溃恢复机制。
    

MyISAM 曾经广泛用于读多写少的场景，但现在大多数常规业务表都会选择 InnoDB。

### 4. InnoDB：现代业务系统的主流选择

例如：

```
CREATE TABLE test_innodb (
    id INT PRIMARY KEY,
    name VARCHAR(50)
) ENGINE = InnoDB;
```

InnoDB 的主要特点：

- 支持事务和 ACID，通过 Undo Log、Redo Log 等机制保证事务特性。
    
- 支持行级锁，可以在很多情况下减少并发事务之间的锁冲突。
    
- 支持 MVCC，普通查询通常不必通过加行锁才能获得一致的数据。
    
- 支持外键约束。
    
- 采用聚簇索引组织表数据，主键索引的叶子节点中存储行记录。
    

你之前学习的事务隔离级别、MVCC、Undo Log、Redo Log，主要都是围绕 InnoDB 展开的。

实际开发中，没有特殊需求，建业务表通常直接使用 InnoDB。

## 二、InnoDB 的逻辑存储结构（重点）

InnoDB 的逻辑存储结构从大到小，可以概括为：

表空间（Tablespace）→ 段（Segment）→ 区（Extent）→ 页（Page）→ 行（Row）

表空间 Tablespace

存储数据和索引的逻辑空间


段 Segment
- InnoDB 的段不仅管理索引结构占用的空间，也管理实际数据所在的空间。
- B+ 树的节点对应的是页（Page），不是区（Extent）。


区 Extent

默认页大小下，1 MB = 64 个连续页


页 Page

默认 16 KB，InnoDB 数据管理和 I/O 的基本单位


行 Row

实际的数据记录，例如一名用户的信息

示意层级。实际分配空间时，段在较小时也能直接分配单独的页，不一定所有页都通过完整的区分配。

### 1. 表空间（Tablespace）

表空间是 InnoDB 管理数据存储的最大逻辑单位。

可以将表空间理解成一个仓库，用来存储表的数据和索引。

InnoDB 有几种常见的表空间：

|类型|用途|
|---|---|
|系统表空间|存储部分 InnoDB 内部系统数据|
|独立表空间|通常一个表对应一个表空间|
|通用表空间|多张表可以共享|
|Undo 表空间|存储 Undo Log|
|临时表空间|存储临时数据|

其中，我们重点理解独立表空间。

例如：

```
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50)
) ENGINE = InnoDB;
```

在默认启用 `innodb_file_per_table` 的情况下，InnoDB 通常为这张表创建：

```
users.ibd
```

这个文件中存储该表的数据和索引。

因此，独立表空间可以简单理解为一张表及其索引所对应的存储空间。

但要注意，表空间是逻辑概念，`.ibd` 是磁盘上的物理文件。

### 2. 段（Segment）

段是表空间内部按照用途划分和管理的一组存储空间。

这里需要联系你后面要学习的 B+ 树索引。

简化的 B+ 树示意，实际一个节点通常对应一个索引页。

InnoDB 通常为一个索引分配两个段：

- 叶子节点段：管理 B+ 树叶子节点占用的空间。
    
- 非叶子节点段：管理 B+ 树非叶子节点占用的空间。
    

为什么要分开？

因为叶子节点与非叶子节点承担的任务不同。分开管理有利于存储空间分配，以及让叶子节点的数据在磁盘上尽可能连续，提高顺序读取效率。

### 3. 区（Extent）

区是由一组连续的数据页构成的空间分配单位。

假设一张表需要存储大量数据。

如果 InnoDB 每次需要增加存储空间，都只申请一个 16KB 的页，那么管理大量页面会比较繁琐，也可能影响空间布局。

### 4. 页（Page）——特别重要

页是 InnoDB 管理磁盘数据和进行数据页 I/O 的基本单位，默认大小是 16KB。

假设：

```
SELECT * FROM users WHERE id = 1;
```

你可能会认为，MySQL 只需要读取 `id = 1` 这一行即可。

但实际上，InnoDB 是按照页来管理和读取数据的。

例如一个 16KB 的数据页：

数据页 Page

16 KB（默认）

Page Header 等管理信息

id = 1，name = 张三

id = 2，name = 李四

id = 3，name = 王五

id = 4，name = 赵六

··· 其他行记录 ···

页目录、页尾等信息

示意图：一个数据页通常存储多条行记录，不是只能存储一行。

如果所需数据页还没有缓存在 Buffer Pool 中，InnoDB 就可能需要从磁盘读取该页到 Buffer Pool，再在页中定位对应的记录。

因此，理解页很重要，因为它关系到：

- 为什么 MySQL 需要 Buffer Pool 缓存。
    
- 为什么 InnoDB 使用 B+ 树组织数据。
    
- 为什么索引查询的效率与磁盘 I/O 有关。
    

### 5. 行（Row）

行就是我们使用 SQL 插入的一条数据记录。

例如：

```
INSERT INTO users (id, name)
VALUES (1, '张三');
```

对应的逻辑记录是：

|id|name|
|---|---|
|1|张三|

但 InnoDB 在实际存储时，不仅仅保存这两个字段，还需要记录额外的管理信息。

例如聚簇索引记录中通常有：

|隐藏字段|作用|
|---|---|
|`DB_TRX_ID`|记录最近修改该行的事务 ID|
|`DB_ROLL_PTR`|指向用于回滚及构造历史版本的 Undo 记录|
|`DB_ROW_ID`|某些没有合适主键的表使用的隐藏行 ID|

这些字段与之前学习的 MVCC 密切相关。

另外，行记录通常存储在数据页中，但如果存在很长的 `TEXT`、`BLOB` 等字段，部分数据也可能存储到其他溢出页中。

## 三、把五个概念串联起来

假设执行：

```
CREATE TABLE student (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50),
    age INT
) ENGINE = InnoDB;
```

然后插入 10 万条学生记录。

从逻辑存储结构理解：

第一步：表空间

默认情况下，这张表对应一个 `student.ibd` 文件，用于存储表数据和索引。

第二步：段

InnoDB 使用 B+ 树存储聚簇索引，通过不同的段管理叶子节点和非叶子节点。

第三步：区

随着数据不断增加，需要更多存储空间时，InnoDB 可以按区分配，每个区在默认配置下为 1 MB。

第四步：页

区中包含若干页，默认一个页是 16 KB。B+ 树的节点存储在这些页中。

第五步：行

聚簇索引的叶子节点页存储具体的学生记录。

所以查询：

```
SELECT * FROM student WHERE id = 100;
```

InnoDB 可以沿着主键 B+ 树，从根节点到叶子节点，最终定位到记录所在的页，再查找目标记录。

这就把表空间、段、区、页、行与 B+ 树索引联系起来了。

## 四、最后总结

|逻辑结构|核心作用|记忆方式|
|---|---|---|
|表空间|管理数据及索引的存储空间|大仓库|
|段|按用途组织和管理存储空间|仓库中的不同区域|
|区|批量分配连续的数据页|一组货架|
|页|数据管理与数据页 I/O 的基本单位|一个货架|
|行|实际的数据记录|货架上的商品|

你目前需要重点记住三个数字或关系：

1. 默认页大小为 `16KB`。

2. 默认情况下，一个区有 `64` 个连续页，共 `1MB`。

3. InnoDB 通过 B+ 树组织索引和数据，聚簇索引的叶子节点页保存实际行记录。

后面继续学习 MySQL 索引时，最值得深化的是为什么 InnoDB 采用 B+ 树，而不是二叉树、红黑树或普通 B 树。理解页和磁盘 I/O 后，这个问题就容易理解得多了。
