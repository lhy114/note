#### 索引
**索引（index）**是帮助MySQL高效获取数据的数据结构（有序）。在数据之外，数据库系统还维护着满足特定查找算法的数据结构，这些数据结构以某种方式引用（指向）数据，这样就可以在这些数据结构上实现高级查找算法，这种数据结构就是索引。

##### B+树和B树
![[Pasted image 20260806145917.png]]
![[Pasted image 20260806150553.png]]

**这里补充为什么不用红黑树**，在数据库中，瓶颈一般是磁盘的IO，树的每一层相当于每次磁盘访问的次数，如果一个数据库很多，那么构建的这个红黑树，高度会很高（几十层），但是由于B树节点的子节点有很多，所以树的高度会控制的很低，通常也就3-4层高度，那么此时访问的IO次数远远小于红黑树。为什么Java的容器会使用红黑树呢，因此容器是在内存之间，我们访问的速度几乎可以忽略，现在的目标就是，简单实现，然后插入删除稳定，中序遍历有序的效果了。
![[Pasted image 20260806151606.png]]![[Pasted image 20260806151818.png]]
**为什么数据库使用的B+树而不是B树呢？**（对于每一个节点我们都是用一个页）
1. **内部节点小，树才能矮**。由于节点现在不存放数据了，现在我们可以把度设置的很大很大，此时存储的指针就会很多。
2. **范围查询可以顺着叶子节点进行查询。** B+ 树的叶子节点按 key 有序排列，并且彼此用指针串成链表（InnoDB 里是双向链表）。范围查询（`BETWEEN`、`> <`、`ORDER BY`）只要定位到第一个满足条件的叶子，然后顺着链表往下读就行，几乎全是顺序 I/O。
3. **查询性能稳定。** B 树里有些数据在高层，碰巧命中能少读两层；但这是不稳定收益，不能依赖。B+ 树所有查询都必然走到叶子层，路径固定、开销可预期，对数据库执行计划更友好。

##### 索引的分类
![[Pasted image 20260806154936.png]]

**InnoDB的索引分为两类**：
1. **聚集索引**，相当于存储的表的物理结构，将**主键进行排序构造成一个B+树**，然后叶子节点存储的**整条数据记录**。
2. **二级索引**，自己建立的索引，叶子节点现在存储的是当前的**索引列+主键**
![[Pasted image 20260806160233.png]]
![[Pasted image 20260806155814.png]]

**回表查询**，当我们执行 select * from emp where name = 'Army'的时候，首先我们会通过二级索引找到对应的主键值，然后通过主键值，我们才能够通过聚集索引得到数据的信息。
- 主键查询：直接进聚簇索引，最快
- 走二级索引的查询：**只有需要的数据在二级索引里拿不全时**，才需要回表
- 覆盖索引：不需要回表
- 全表扫描：连索引都不走，直接把表（聚簇索引叶子）全读一遍
--------------------------------------------------------------------
- 条件是主键 → 走聚簇索引，不进二级索引
- 条件是非主键列且建了索引 → 走二级索引，可能要回表
- 条件是非主键列且没建索引 → 全表扫描
- 查询返回的列二级索引全覆盖 → 走二级索引但不回表
